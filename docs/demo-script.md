# Сценарий защиты (~7 минут + вопросы)

**Подготовка (за 10 минут до защиты):** `run.bat` (данные уже загружены — обновление ~30 с), дашборд открыт
на странице «Прогноз». Проверить в «Журнале», что последний запуск зелёный.

## 1. Селиванова — задача и погода (2,5 мин)

1. Постановка: ORD, кто пользователь (операционный менеджер), что прогнозируем. Три источника, почему США.
2. Страница **«Погода и задержки»**:
   - показать сырой METAR (`KORD 161451Z 27015G25KT 3SM -SN BR OVC008 …`) и что из него извлекается —
     это слабоструктурированные данные;
   - «Какие условия бьют сильнее»: гроза 67%, снег 46%, без явлений 23% — каждый вылет сопоставлен с погодой;
   - «Из-за чего задержки»: погода официально 9%, но прячется в NAS и «позднем прилёте»;
   - тепловая карта: к вечеру задержки копятся.
3. Прогноз погоды на неделю — переход к прогнозу задержек.

## 2. Козлов — прогноз (2,5 мин)

1. Страница **«Прогноз»**: KPI, главный график — прогноз против нормы на 7 дней, полоса интервала.
   Подвигать слайдер порога → показать вывод «в какие дни нужен резерв».
2. Почему прогноз по погоде: BTS публикуется с лагом 2–3 мес.
3. «Насколько можно верить»: backtest — модель лучше нормы на 21% (задержки) и 54% (рейсы).
   Раскрыть «Что модель считает важным» — гроза и видимость наверху.
4. Честно про ограничения: ошибка 8 п.п., погода — не единственная причина.

## 3. Харлашкина — данные и надёжность (2 мин)

1. Страница **«Журнал и качество»**: схема пайплайна, журнал запусков.
2. **Демо устойчивости**: «Демо-режим сбоев» → «лимит запросов (429)» → «Обновить данные сейчас»:
   видно ретраи, загрузка проходит. Затем «таймаут источников» → источники `failed`, остальные шаги работают.
3. Повторный запуск без сбоев → «новых 0»: инкрементальность и идемпотентность.
4. Проверки качества: найденные реальные проблемы (задержки > 33 ч, битый METAR, праздники).
5. Страница **«Данные»**: исправить задержку у рейса → флаг «Правлен вручную», запись в журнале правок;
   объяснить, что повторная загрузка правку не перезапишет.

## Частые вопросы — кто отвечает

| Вопрос | Кто | Короткий ответ |
|---|---|---|
| Где слабоструктурированные данные? | Селиванова | METAR — свободный текст по стандарту ВМО, разбираем в признаки |
| Почему не российские аэропорты? | Селиванова | статистика задержек в РФ не публикуется |
| Что будет, если источник недоступен? | Харлашкина | ретраи → ошибка в журнале → остальные шаги идут; BTS можно загрузить вручную ZIP-ом |
| Как проверяли, что повтор ничего не задваивает? | Харлашкина | тесты + повторный запуск на живых данных: 0 новых строк |
| Почему модель не точнее? | Козлов | погода объясняет часть; каскадные задержки и сеть не видны в данных одного аэропорта |
| Нет ли утечки будущего? | Козлов | лаги ≥ 364 дней, тест на изменение будущего |
| Почему при LIFR задержек меньше, чем при IFR? | Селиванова | в LIFR чаще отменяют рейсы, а отмены не входят в долю задержек |
| Почему SQLite/Streamlit? | любой | `docs/architecture.md`, таблица «Стек и почему» |
