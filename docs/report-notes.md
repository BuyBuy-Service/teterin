## 1. Постановка задачи (Селиванова)

Разработать прототип прогнозно-аналитической системы для аэропорта Chicago O'Hare (ORD): сбор данных
о рейсах и погоде, хранение, очистка, контроль качества, прогноз числа вылетов и доли задержек на 7 дней,
интерактивный дашборд для операционного менеджера. Тема №7 «Гражданская авиация» из списка преподавателя.
Российские аэропорты не используются: официальная статистика задержек в РФ не публикуется.

## 2. Предметная область (Селиванова)

- Задержка рейса по стандарту DOT США — вылет позже расписания на 15 мин и больше (`DepDel15`).
- Перевозчики сами указывают причины задержки: перевозчик, поздний прилёт самолёта, авиасистема (NAS),
  погода, безопасность.
- METAR — стандартная авиационная сводка погоды, выпускается ежечасно и внепланово при изменении погоды.
- Категории полётных условий FAA: VFR / MVFR / IFR / LIFR — по видимости и высоте нижней границы облаков.
- ORD — один из крупнейших хабов США: ~900 выполненных вылетов в день, 13 перевозчиков, крупнейший — United.

## 3. Данные (Харлашкина — BTS; Селиванова — METAR, Open-Meteo)

См. `docs/sources.md`. Три разнородных источника: пакетные ZIP/CSV (BTS), текстовые сводки (METAR —
**слабоструктурированные данные**: текст + показания датчиков), JSON API (Open-Meteo).
История: 09.2024–08.2026, 1,34 млн рейсов (668 тыс. вылетов), 23,6 тыс. METAR-сводок.

## 4. Решения по обработке данных

- **(Харлашкина)** Инкрементальность: watermark по каждому источнику; повторный запуск догружает только новое
  (проверено: 2-й запуск — 0 новых строк по всем источникам). Идемпотентность: upsert по естественным ключам,
  sha256 файлов и ответов, данные и watermark — в одной транзакции. Устойчивость: таймауты, ретраи
  с экспоненциальной паузой и учётом `Retry-After`, карантин битых файлов, ошибка одного шага не валит цепочку,
  защита от параллельного запуска, валидация параметров. Журнал загрузок `load_log`. Ручные правки защищены
  флагом `is_manual`, удаление мягкое. Контроль качества — `docs/dq.md`.
- **(Селиванова)** Разбор METAR: числовые группы — библиотекой `metar`, погодные явления — собственным разбором
  токенов; категория VFR/IFR по правилам FAA. Разобрано 23 587 из 23 588 сводок. Каждый вылет сопоставлен с
  последней сводкой не старше 90 минут до планового вылета (`merge_asof`), с переводом местного времени в UTC.
- **(Козлов)** Витрина `daily`: день × рейсы × погода; признаки погоды считаются одинаково по факту (METAR) и
  прогнозу (Open-Meteo). Модель — `docs/model.md`.

## 6. Выводы (каждый — по своей части, общий абзац — Селиванова)

- Погода — сильный фактор пунктуальности: при грозе задержано 67% вылетов, при ледяном дожде 54%,
  при снеге 46%, без опасных явлений 23% (среднее 25%).
- В отчётности перевозчиков «погода» — лишь 9% минут задержки; основная часть — поздний прилёт самолёта
  (41%) и перевозчик (29%), NAS — 21%. Погодные задержки часто записываются в NAS и «поздний прилёт».
- Задержки накапливаются к вечеру: доля задержанных вылетов растёт с ~10% в 5–7 утра до 35–38% в 19–22 часа.
- Модель лучше нормы: по доле задержек на 21%, по числу вылетов на 54%.

## 7. Ограничения

- **Лаг BTS** 2–3 месяца: факт о задержках приходит с опозданием, оценка «живого» прогноза — тоже.
- **Одна точка данных**: только ORD; погода в других аэропортах и загрузка сети не учитываются.
- **Нет будущего расписания**: число рейсов прогнозируется по прошлому году и сезону.
- **Прогноз погоды ≠ факт**: модель обучена на фактической погоде, работает на прогнозе; backtest оптимистичен.
- **Высоты облаков нет в прогнозе Open-Meteo**: категорию IFR для будущих дней оцениваем по видимости.
- **Редкие явления** (ледяной дождь, туман) представлены сотнями вылетов — оценки по ним менее надёжны.
- Отменённые рейсы не входят в долю задержек: в очень плохую погоду (LIFR) часть рейсов отменяют, поэтому
  доля задержек при LIFR (30%) ниже, чем при IFR (34%).
