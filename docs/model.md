# Прогнозная модель (часть C)

Код — `marts.py` (витрина), `model.py` (модель). Обучение и прогноз — при каждом запуске цепочки (~10 с).

## Постановка

Дневной уровень, вылеты из ORD, две цели:
1. **доля вылетов с задержкой ≥ 15 мин** (`dep_del15_share`);
2. **число выполненных вылетов** (`dep_flown`).

Горизонт: от последнего месяца BTS до сегодня + 7 дней. BTS публикуется с лагом 2–3 месяца, поэтому
для дней после последнего месяца модель прогнозирует по погоде: прошедшие дни — по фактическому METAR,
будущие — по прогнозу Open-Meteo. Когда BTS публикует новый месяц, заранее сделанные прогнозы
сравниваются с фактом автоматически (блок «Живая проверка» на странице «Прогноз»).

## Признаки

- календарь: день недели, месяц, сезон (sin/cos дня года), расстояние до ближайшего праздника США;
- погода дня: мин. видимость, макс. порывы, часы с осадками, часы с видимостью < 3 миль, флаги дождя, снега,
  ледяного дождя, грозы, тумана;
- для числа рейсов — значение того же дня недели год назад (364 дня).

Признаки выбраны так, чтобы считаться **одинаково по METAR и по прогнозу Open-Meteo**: высоту облаков прогноз
не даёт, поэтому категория IFR в модель не входит (только видимость). Иначе модель училась бы на одном
признаке, а прогнозировала бы по другому.

**Утечки будущего нет**: нет лагов короче 364 дней; тест `tests/test_model.py` проверяет, что изменение
будущих данных не меняет прогноз на прошлое.

## Модель, бейзлайн, интервалы

- Модель: `HistGradientBoostingRegressor` (loss — абсолютная ошибка, т.е. прогноз медианы).
- Бейзлайн («норма»): для доли задержек — среднее по (день недели, месяц); для числа рейсов — тот же день
  недели год назад (среднее по годам занижало норму: расписание ORD за 2 года выросло ~на 15%).
- Интервал 10–90%: прогноз + квантили ошибок модели на backtest. Сначала пробовали квантильные бустинги —
  они переобучались, покрытие было 32–54% вместо 80%.

## Проверка (rolling-origin backtest)

Каждый из последних 6 месяцев (03–08.2026, 184 дня) прогнозируется моделью, обученной только на данных до него.

| Цель | MAE модели | MAE нормы | Выигрыш | MAPE модели | Покрытие интервала |
|---|---|---|---|---|---|
| Доля задержек | **8,3 п.п.** | 10,6 п.п. | −21% | 28% | 77% |
| Число вылетов | **66 рейсов** | 143 рейса | −54% | 6,9% | 68% |

Важнее всего для доли задержек (permutation importance): гроза, минимальная видимость, сезон, день недели, порывы.

## Ограничения

- Задержки предсказываются умеренно: средняя доля 25%, ошибка 8 п.п. Погода аэропорта объясняет только часть —
  каскадные задержки, загрузка сети, погода в других аэропортах в данных не видны.
- В backtest использована фактическая погода («идеальный прогноз погоды») — на реальном прогнозе точность ниже.
- Нет будущего расписания: модель почти не различает дни недели в числе рейсов.
- Только один аэропорт и ~730 дней истории; редкие явления (ледяной дождь — 547 вылетов) представлены слабо.
